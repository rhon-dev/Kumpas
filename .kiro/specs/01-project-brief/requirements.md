# Phase 1 — Project Brief

## Objective

Document the exact problem and thesis contribution with sufficient rigor for thesis-committee defense.

## Requirements

WHEN the project brief is finalized,
the system SHALL document the precise problem statement distinguishing Kumpas from existing FSL/ASL recognition research.

WHEN the project brief is finalized,
the system SHALL explicitly state the novelty claim: corrective feedback across four dimensions (handshape, orientation, motion, timing), not classification itself.

WHEN the project brief is finalized,
the system SHALL define target users, constraints, and an explicit out-of-scope list.

WHEN the project brief is finalized,
the system SHALL define measurable success criteria tied to numeric targets (≥90% accuracy, <150ms latency, 24–30 FPS).

## Acceptance Criteria

1. Problem statement clearly distinguishes "feedback" from "classification" as the thesis contribution.
2. Target users are named with their primary use case.
3. Constraints are enumerable and testable.
4. Success criteria are numeric, post-quantization, on-device — not aspirational.
5. Out-of-scope list matches Section 6.2 of the SDLC kickoff.
