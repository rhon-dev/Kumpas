# Phase 16 — Evaluation Study Design

## Objective

Design a defensible pre/post study suitable for thesis defense, with appropriate statistical methodology.

## Requirements

WHEN the study is designed,
the system SHALL specify: what is measured before and after using Kumpas (sign accuracy rubric), how "improvement" is operationalized.

WHEN participant count is decided,
the system SHALL document the reasoning (power analysis if feasible, or practical constraints with acknowledged limitations).

WHEN the statistical test is selected,
the system SHALL justify the choice (paired t-test, Wilcoxon, etc.) based on expected data distribution and sample size.

WHEN consent is designed,
the system SHALL produce language suitable for IRB-equivalent review, covering: what data is collected, how it is stored, how long it is retained, right to withdraw.

WHEN study data handling is specified,
the system SHALL confirm: study recordings/data are separate from training data, stored locally only, deleted per retention policy.

## Acceptance Criteria

1. Study protocol is complete enough for an ethics review.
2. Statistical test choice is justified (not "we always use t-tests").
3. Sample-size reasoning is documented (even if "practical constraint, not power analysis").
4. Consent form draft exists.
5. Explicit flag if statistician consultation is recommended.
6. Data-handling for study recordings is documented separately from FSL-105 data rules.
